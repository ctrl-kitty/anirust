# Anirust Android

Android-клиент на Kotlin, Jetpack Compose и Material 3. Минимальная версия Android — 7.0 (API 24).

## Возможности

- Поиск в Yummy с дополнением метаданными Shikimori, отменой устаревших запросов и повтором после ошибки.
- Информация об аниме, порядок просмотра, доступные серии и выбор озвучки. В списке только поддерживаемые Kodik и прямые потоки.
- Встроенный Media3-плеер: HLS, HTTP-заголовки, управление воспроизведением, субтитры, восстановление позиции и освобождение ресурсов при уходе в фон.
- Локальная история и продолжение просмотра. Позиция сохраняется каждые 5 секунд и при закрытии плеера; завершённая серия при повторном открытии начинается сначала.
- Личные списки: «Смотрю», «В планах», «Просмотрено», «Любимое». Статус меняется кнопкой закладки в карточке аниме.
- Аккаунт Shikimori: шесть статусов списков, оценки, просмотренные серии, обновление при возвращении в приложение и ручная синхронизация. Подтверждённые изменения локальных и облачных списков сопровождаются Toast.
- Просмотр из списков Shikimori: «Выбрать серию» открывает карточку с озвучками и плеером. Соответствие каталогу проверяется по ID, а не только по названию.
- Предпочитаемая озвучка, выбор встроенного или внешнего плеера, удаление истории и закладок с подтверждением.
- Интерфейс Material 3: светлая и тёмная системные темы, тональные поверхности, крупная типографика, доступные зоны нажатия.
- Нижняя навигация на телефоне и боковая панель от 600 dp; описание и серии в двух колонках от 840 dp. Ширина длинного текста ограничена.
- Выбор озвучки в нижней шторке, меню дополнительных действий у серий и истории, подтверждение удаления, поиск с подсказками.
- Озвучка запоминается отдельно для аниме и его подтверждённых ID в каталогах. Приоритет: личный выбор → последняя озвучка из истории → общая настройка. «Все» тоже сохраняется; при отсутствии сохранённой озвучки показывается предупреждение.
- Сезоны и части выбираются в прокручиваемой шторке: полные названия, порядок просмотра и текущая часть. Компактный блок на странице не вытесняет серии.
- Поиск сохраняет сетку и её положение во время ввода/загрузки; обновление показывается тонким индикатором. Карточки Yummy появляются до завершения загрузки метаданных Shikimori, затем уточняются. Устаревшие ответы не заменяют новый запрос.
- Адаптивные сетки, учёт системных отступов и клавиатуры, векторная иконка приложения.

## Сборка

Нужны JDK 21, Android SDK Platform 36 и совместимые Android Build Tools. В Android Studio откройте каталог `android/`; путь SDK задаётся в `local.properties` или через `ANDROID_HOME`.

Общие реквизиты OAuth подставляются в `BuildConfig` при сборке. Разработчику нужно создать `android/oauth.properties` по образцу `oauth.properties.example` и заполнить `SHIKIMORI_CLIENT_SECRET`; файл исключён из Git. В CI можно задать `SHIKIMORI_CLIENT_ID`, `SHIKIMORI_CLIENT_SECRET`, `SHIKIMORI_APP_NAME` через переменные окружения. Имя приложения должно совпадать с зарегистрированным в Shikimori. Без секрета сборка прекращается с сообщением о настройке, не печатая его значение. Пользователям готового APK эти настройки не нужны.

Из каталога `android/`:

```bash
nix-shell
./gradlew testDebugUnitTest assembleDebug lintDebug
```

`shell.nix` использует существующий `ANDROID_HOME` или `$HOME/Android/Sdk`. Без Nix те же команды Gradle работают при настроенных Java и SDK.

APK: `app/build/outputs/apk/debug/app-debug.apk`. Если локальный `debug.keystore` уже существует, он сохраняется для совместимости обновлений. Иначе используется стандартный отладочный ключ Android Gradle Plugin; ключ в репозитории не требуется.

```bash
./gradlew assembleRelease
```

Release-сборка включает R8 и удаление неиспользуемых ресурсов. Для распространения подпишите её собственным ключом: release-ключ и пароли в репозитории не хранятся.

Для проверки плавности на телефоне используйте `./gradlew assemblePreview`: `app/build/outputs/apk/preview/app-preview.apk` оптимизирован как release, но подписан локальным debug-ключом для установки поверх debug без удаления данных. Это не ключ для публикации. Сравнивать плавность нужно на одном устройстве; Robolectric не измеряет реальный FPS.

## Проверки

Обычные тесты не зависят от сети. Они проверяют реальные формы JSON, разделение ID провайдеров, обработку сетевых ошибок, фильтрацию озвучек, отмену поиска, Room, сохранение позиции, смену сезона и навигацию Compose.

Robolectric-тесты интерфейса сохраняют изображения в `app/build/reports/ui/`; HTML-отчёт тестов находится в `app/build/reports/tests/testDebugUnitTest/index.html`.

Опциональная проверка живых провайдеров (поиск → информация → серии → Kodik → HLS-плейлист):

```bash
ANIRUST_LIVE_TESTS=1 ./gradlew testDebugUnitTest --tests com.anirust.app.LiveProviderTest --rerun-tasks
```

Тест зависит от доступности провайдеров, CDN и региона. Он не подтверждает работу декодера на конкретном устройстве. Для этого установите APK и проверьте воспроизведение, поворот экрана, уход в фон и продолжение просмотра.

## Внешние плееры

MPV, mpvEx, VLC и системный выбор доступны в настройках: включите «Открывать во внешнем плеере» и выберите приложение. Плеер нужно установить отдельно. При отсутствии выбранного приложения открывается системный выбор. Передаётся сохранённая позиция; внешний плеер самостоятельно управляет дальнейшим прогрессом, который приложение не получает обратно.

HTTP-заголовки передаются как совместимые intent extras, но поддержка зависит от приложения. Для [mpvEx](https://github.com/marlboro-advance/mpvEx/blob/master/app/src/main/java/app/marlboroadvance/mpvex/ui/player/PlayerActivity.kt) передаётся массив пар с User-Agent первым, затем Referer/Origin и остальные заголовки; позиция — целое число миллисекунд. В частности, [stock mpv-android пока не читает headers](https://github.com/mpv-android/mpv-android/blob/master/app/src/main/java/is/xyz/mpv/MPVActivity.kt). Если поток не открывается во внешнем приложении, используйте встроенный плеер.

## Подключение Shikimori

1. В настройках откройте «Аккаунт Shikimori» и нажмите «Войти через Shikimori».
2. Подтвердите доступ AniRust в браузере и скопируйте показанный одноразовый код.
3. Вставьте код в единственное поле и нажмите «Подключить Shikimori». Пароль вводится только на сайте; создавать своё OAuth-приложение пользователю не нужно.

Используется общее OAuth-приложение AniRust с Redirect URI `urn:ietf:wg:oauth:2.0:oob` и разрешением `user_rates`. Client Secret встроен в APK: отсутствие его в Git и обфускация не делают его конфиденциальным для получателей APK. Персональные токены не встроены в приложение и не попадают в HTTP-логи. Уже подключённые аккаунты сохраняют прежнюю сессию; новые входы используют общие реквизиты сборки.

После подключения вкладка «Списки» сразу показывает Shikimori, по умолчанию «Смотрю». Если есть локальные закладки, показывается предупреждение о замене: только после «Заменить локальные» они удаляются, а источником списков становится аккаунт и его зашифрованная копия. «Пока сохранить» не удаляет записи и не отправляет их на сайт. После отключения аккаунта снова доступны оставшиеся локальные записи; удалённые при подтверждении закладки не восстанавливаются. История и выбор озвучки сохраняются.

В карточке аниме можно добавить запись в Shikimori, изменить статус, оценку и число серий; удаление требует подтверждения. При подключённом аккаунте кнопка закладки редактирует Shikimori. Число просмотренных серий меняется вручную: воспроизведение не отмечает серию просмотренной в Shikimori автоматически. Галочки отображают первые N серий из счётчика Shikimori плюс локально досмотренные серии, а не просто открытые. Изменение счётчика и синхронизация обновляют галочки без перезапуска страницы.

Локальные закладки и история не загружаются в облако автоматически. Без сети доступна последняя сохранённая копия; изменения не ставятся в офлайн-очередь. Если в каталоге нет подтверждённого соответствия или поддерживаемого потока, приложение сообщает об этом и не подставляет другое аниме.

На странице аниме по умолчанию включён фильтр «Новые»: просмотренные по Shikimori или локальной истории серии скрыты. «Все» возвращает их в список. Если новых серий нет, показывается «Нет непросмотренных серий» и кнопка «Показать просмотренные». Фильтр учитывает выбранную озвучку и сбрасывается на «Новые» при смене части.

OAuth refresh-токены обновляются автоматически. Секрет, токены и копия списков хранятся в AES-GCM-файле с ключом Android Keystore, вне резервных копий; OAuth-клиент не ведёт HTTP-логи. Отключение аккаунта удаляет локальную сессию, не затрагивая списки на сайте. Доступ можно отозвать в настройках Shikimori.

Чтение списков использует GraphQL с пагинацией, изменения — API v2; [документация Shikimori](https://shikimori.io/api/doc). Автоматические тесты аккаунта используют поддельный серверный слой и не меняют реальные списки; полный вход и синхронизацию нужно дополнительно проверить на устройстве с одноразовым кодом.

## Структура и данные

- `data/remote/`: Retrofit/Moshi API и отменяемый Kodik resolver.
- `data/local/`: Room, история и личные списки.
- `domain/`: модели и use cases.
- `ui/`: экраны, ViewModel, навигация и тема.
- `di/AppContainer.kt`: сборка зависимостей.

ID внутри приложения: положительные значения — Yummy, отрицательные — информационные записи Shikimori. Поиск соответствия выполняется по внешним ID, без подстановки первого похожего названия.

История и локальные закладки хранятся в Room; сессия Shikimori и копия облачных списков — отдельно в зашифрованном хранилище. Схема Room не сбрасывается автоматически при обновлении: изменения схемы требуют явной миграции. Обычные HTTP-медиа разрешены для совместимости с прямыми потоками; API каталога использует HTTPS. Сетевые логи отключены в release.
